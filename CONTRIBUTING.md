Thanks for your interest. Issues and pull requests are welcome: bug
reports, data or method corrections, new study sites and docs fixes.

## Local development

See [`docs/GUIDE.md`](docs/GUIDE.md) for step-by-step setup on macOS,
Linux and Windows, and [`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md) for
day-to-day commands. TL;DR:

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
flask db upgrade
flask nisar load       # load the study sites from app/data/
bin/start dev          # backend on :8880

# in another terminal
cd frontend
npm install
npm run dev            # frontend on :5173
```

## Conventions

- **One blueprint per concern.** Add new endpoints to
  `app/routes/api.py` (or split into a new blueprint and register it in
  `app/__init__.py`). Always wrap with `@limiter.limit(...)`.
- **Models change → migration.** `flask db migrate -m "<change>"` then
  inspect the file under `app/migrations/versions/`. CI runs
  `flask nisar check-schema` and fails the build if a migration is
  missing.
- **Data comes from NISAR, never made up.** Values and images in
  `app/data/` are generated by `scripts/extract_nisar.py`; regenerate
  them rather than editing by hand, and commit the result.
- **Tests live in their own folders.** Backend: `tests/test_<area>.py`.
  Frontend: `frontend/src/test/<Component>.test.jsx`.
- **Numbers in docs come from the data.** After the data changes, run
  `python scripts/chain_evidence.py --write` to refresh the tables in
  `docs/DATA_AND_METHODS.md`, and update any prose that quotes them.

## Tests

| What        | Command                                                        |
| ----------- | -------------------------------------------------------------- |
| Backend     | `pytest tests/ -v`                                             |
| Frontend    | `cd frontend && npm test`                                      |
| Lint (JS)   | `cd frontend && npm run lint`                                  |
| Schema gate | `flask nisar check-schema`                                     |
| Full local  | `pytest tests/ -q && cd frontend && npm test && npm run build` |

## Pull requests

- Branch off `main`.
- Run the test suites locally before pushing — CI runs the same checks
  but failing locally first is faster.
- Keep PRs scoped: schema change + migration + route + test in one PR
  beats four PRs that each leave the tree half-broken.
- Found a wrong number or an overstated claim? Open an issue with the
  site, the date and what you expected; corrections are logged in
  `docs/DATA_AND_METHODS.md` (Corrections).
